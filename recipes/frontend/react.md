# React

The React web frontend Stack Recipe. It follows `recipes/frontend/architecture.md`, `recipes/frontend/libraries.md` and `recipes/frontend/security.md`; this file is how to **generate** the repository so that every Quality Gate passes. Learned from generating one end to end and opening it in a browser against a real backend.

## Generating the project

1. **Tooling**: Node on the latest LTS and pnpm through Corepack, pinned (`.nvmrc`, `engines`, `packageManager`). With no Node on the machine, generation can run in a `node:lts` container (see Dev container below for the file-watching caveat).
2. **Check peer dependencies before settling on versions.** "Latest" is not always installable together: `typescript-eslint` accepts TypeScript only below its stated ceiling (it held the project on TypeScript 6.0 while 7.0 was `latest`), the ESLint React and accessibility plugins stopped at ESLint 9 (while 10 was `latest`), Vitest's mocker accepts MSW 2 only, and `@types/node` must match the Node LTS, not the newest. `strictPeerDependencies: true` in `pnpm-workspace.yaml` makes every such conflict fail at install time instead of surfacing later; resolve each by taking the newest version the rest of the stack supports.
3. **pnpm 12 settings live in `pnpm-workspace.yaml`**, not `.npmrc`: `allowBuilds` (pnpm blocks dependency install scripts by default; allow `esbuild`, explicitly deny the others), `strictPeerDependencies`. `savePrefix` is not honoured, so strip the `^` from `package.json` afterwards (the lockfile has the resolved versions) to keep versions exact.
4. **TypeScript 6**: no `baseUrl`; the `paths` entries start with `./src/…`. Strict flags as in `recipes/frontend/architecture.md`.
5. **Design system**: `shadcn` with `components.json` aliases pointing at `@components/atoms` and `@shared/utils/merge-class-names`. The class-merging helper is named **`mergeClassNames`** (`shared/utils/merge-class-names.ts`, `twMerge(clsx(inputs))`), not shadcn's `cn`: a two-letter abbreviation breaks "names say what things are" (`recipes/coding-standards.md`). The CLI knows only `cn`, and it mis-resolves a `utils` alias that is not of the form `@/lib/utils`: it wrote `from "cn"` and then **installed the unrelated npm package `cn`** to satisfy it. After every `shadcn add`: replace each `import { cn } from "…"` with `import { mergeClassNames } from '@shared/utils/merge-class-names'` and every `cn(` with `mergeClassNames(`, and read `package.json` for dependencies you did not choose. Then split each file into one component per folder (`recipes/frontend/architecture.md`) and keep only the parts used.
6. **API client**: `orval` with two outputs over the same `openapi/openapi.json` (`client: 'axios-functions'` with MSW mocks, then Zod), the mutator in `shared/http/client.ts`, and `@faker-js/faker` installed because the generated mocks import it. **The services layer only calls the endpoint**: `axios-functions` makes each endpoint a plain exported function (`export const healthShow = (options) => httpClient<HealthShow200>({ url: '/health', method: 'GET' }, options)`; plain `axios` wraps them in a `getHealth()` factory, which is noise); set no `schemas` option (no `model/` folder: orval then writes all the endpoints' types into one `<title>.schemas.ts` at the root of `services/`), `indexFiles: false` (no barrels) and never `client: 'react-query'`. TanStack Query is not generated: the screen's hook calls `useQuery` / `useMutation` over the call function, passing the abort `signal` through the options (`queryFn: ({ signal }) => healthShow({ signal })`) and importing the response type from the service file. **Generated files carry no comments** (`recipes/coding-standards.md`, Comments): orval writes a banner and the endpoint's summary as JSDoc, and only the properties' JSDoc can be filtered by option, so `scripts/strip-generated-comments.mjs` removes every block and full-line comment from `src/services` right after orval, as the last step of `project openapi` (and so of `openapi:check`). orval names the types file after the OpenAPI `info.title` in camelCase (`taskBoard.schemas.ts` for the project `task-board`), so a project whose slug differs from the template's changes that file name and the one import of it in the page hook; regenerate with `project openapi` and fix the import. `src/services` is committed, and excluded from lint, formatting, coverage and duplication checks. `scripts/fetch-openapi.mjs` copies the backend's file from a local path (`BACKEND_OPENAPI_FILE`, for a run on the host with the backend beside) or reads it from GitHub (`BACKEND_REPOSITORY`, `GITHUB_TOKEN` when private), and with **no source set it keeps the committed `openapi/openapi.json`**, so `openapi:check` works offline and inside the container (it then proves the committed client matches the committed contract; CI sets `BACKEND_REPOSITORY` to also prove the contract is the backend's current one); `scripts/check-generated.mjs` regenerates and fails when anything changed (no Git needed).
7. **HTTP client** (`shared/http/client.ts`): axios with `withCredentials`, `X-Requested-With`, `Accept-Language` and `X-Timezone` on every request, and an interceptor that turns every failure into an `ApiError` (`shared/types`, because the screens' hooks need it and may not import `shared/http`) carrying the Problem Details `code` and `traceId`; a network failure becomes an `ApiError` without a problem. The interceptor always rejects with an `Error`.
8. **No `app/` folder and no root component**: `src/main.tsx` renders `<AppProviders><RouterProvider router={router} /></AppProviders>`, `src/providers.tsx` holds `AppProviders` (the query client and the color-scheme hook) and `src/router.tsx` the routes, with their tests beside them (`providers.spec.tsx`, `router.spec.tsx`) and their types in `src/types/`. The router uses `createBrowserRouter`, one lazy route per page, and a `HydrateFallback` (the loading organism) on the route, otherwise React Router warns in the console on first load.
9. **Tests**: Vitest with two projects, `unit` (`*.spec.ts`) and `integration` (`*.spec.tsx`), run with `--project`; jsdom; MSW (`setupServer`) with the handlers orval generated; the API URL set in `test.env`; `hookTimeout` raised and the lazy page preloaded in `beforeAll` where a test renders the router, because the first dynamic import is slow on a shared file system. Helpers in `src/test/`: the server, `renderWithProviders` (a fresh query client per test), a Problem Details builder, a `matchMedia` stub and `expectNoAccessibilityViolations` over axe-core. Coverage thresholds 80% for lines, statements, functions and branches, excluding `components/atoms`, `services` and test files.
10. **Lint**: flat ESLint config with typed linting (`projectService`), the React, hooks and a11y rules, `react/no-danger`, `react/no-multi-comp`, no default exports, `simple-import-sort`, `check-file` naming (files kebab-case, hooks camelCase, component folders kebab-case, `index.spec` blocked), and the size and complexity limits of `recipes/coding-standards.md`. Two structural rules through `no-restricted-syntax` and `no-restricted-imports`: **types only in `types/` folders** (the selectors `TSTypeAliasDeclaration`, `TSInterfaceDeclaration` and `TSTypeLiteral`, off in `types/`, in `*.d.ts` and, for object type literals, in specs; the block that relaxes rules for tests must keep the `types/` exemption, so it sets this rule in its own block with `ignores: ['src/**/types/**']`: a later flat-config block replaces the rule entirely and would otherwise flag `src/test/types/`) and **little logic in a component file** (`max-statements` 5 on the `.tsx` files that are not specs, on top of the 30-line function limit, so anything beyond a few statements moves to the page's hook). Config and script files are excluded from typed linting. `prettier --check` and `jscpd` run in the same `lint` script.
11. **Architecture**: dependency-cruiser rules mirroring the five rules of `recipes/frontend/architecture.md` (rule 3 allows `services/` and `state/` only from the `hooks/` folders of pages), plus no cycles and no barrel files. A page's hook builds its view model from the types declared by the sections it feeds, imported from their `types/` (`health-panel/types/health-panel-view.ts` reuses the props types of the molecules and organisms it renders, and `pages/home/hooks/useHome.ts` returns it).
12. **Dependency audit**: `scripts/audit.mjs` over `pnpm audit --json` with `audit-allowlist.json` (id, package, reason, expiry date). `pnpm audit` is a built-in command and ignores a script of that name, so the script is called with `pnpm run audit`.
13. **Brand Tokens** as CSS variables in `src/index.css` (colors in `oklch`, radius, font). The primary color comes from the interview as `#rrggbb` and is converted with `.claude/skills/new-project/tools/brand-tokens.mjs`, which prints the primary, its foreground (light or dark by lightness), the ring and the dark-mode variants; the other tokens (background, card, muted, border…) keep the neutral set. The radius is 0.25rem (sharp), 0.625rem (default) or 1rem (round). The font is the system stack unless a named one is chosen: then it is installed from the self-hosted package `@fontsource-variable/<font>` (no request to a third party at runtime), imported as the first line of `main.tsx` (`import '@fontsource-variable/inter';`) and named in `--font-sans` as `'Inter Variable'`. **Dark mode yes**: the `.dark` block, `@custom-variant dark` and the color-scheme hook called by `AppProviders`; **dark mode no**: none of the three exists in the output, and the hook's file and spec are not generated.
14. **Favicon** in `public/` and linked from `index.html`; the browser requests it otherwise and the console shows a 404.
15. **Dockerfile, Compose and dev container**, laid out like a backend's so the pieces are easy to find:
    - `Dockerfile` with only a `dev` target (an SPA has no `prod` image; its output is static files on the CDN). It starts from `mcr.microsoft.com/devcontainers/javascript-node:<node major>-bookworm` (check the tag exists; it brings Git and the `node` user), runs `corepack enable` as root at build time, creates `/app/node_modules` owned by `node` (a new named volume inherits that ownership, so no `sudo chown` at runtime), switches to `USER node`, sets `ENV VITE_USE_POLLING=true` and ends in `CMD ["sleep", "infinity"]`: the container starts idle and the server runs only through `project start:dev` (pnpm 12 installs missing dependencies by itself before running a script, so `start:dev` works even on a fresh volume).
    - `docker-compose.yml` with one service, `app`: build target `dev`, port 5173, the repository bind-mounted at `/app` and `node_modules` in a named volume mounted over it (fast, and the container's Linux dependencies never mix with a host install).
    - `.devcontainer/devcontainer.json` uses that Compose file alone (the service is already idle, so no override file), `workspaceFolder` `/app`, `forwardPorts` 5173, `postCreateCommand` `./project setup` and the extensions of `recipes/vscode-extensions.md`.
    - `project setup` enables Corepack only when `pnpm` is missing, so it works on the host and in the container.
    - `vite.config.ts` turns on `server.watch.usePolling` when `VITE_USE_POLLING` is `true`, because inotify events do not cross a Windows or macOS bind mount and Vite would otherwise serve stale code.
    - The browser runs on the host, so `VITE_API_URL` keeps pointing at `http://localhost:8080`.
    - Never run the container as root (not even once with `--user root` on project folders, and never a `docker run` without `USER node`): a folder created as root on the bind mount (`coverage/`, `dist/`, `openapi/`, `src/services/`) cannot be written or cleaned by the `node` user afterwards (`EACCES`). If it already happened, fix the owner with `docker compose run --rm --user root app chown -R node:node <folder>` (with Git Bash set `MSYS_NO_PATHCONV=1`, which otherwise rewrites `/app` into a Windows path).
    - Prove it before trusting it: `docker compose build app`, then `docker compose run --rm app ./project setup`, `project typecheck` and `project test:unit`, then `docker compose up -d app` and check that port 5173 does **not** answer, run `./project start:dev` from the host terminal and check that it does, and that editing a file on the host changes what the server serves; restarting the container must leave the port silent again.
16. **Strip comments last** (`recipes/coding-standards.md`, Comments): delete full-line comments and one-line JSDoc, keep directives such as `/// <reference types="vite/client" />`, run the formatter and every gate again.
17. **Lefthook** as an exact `devDependency` (`lefthook`), allowed in `allowBuilds`, and `lefthook install` in `project setup` (`recipes/agent-rules.md`, Lefthook).
18. **The interview's answers** (`recipes/new-project.md`) reach the frontend like this: the project name gives the repository `<slug>-frontend`, the dev container and Compose names; the product name goes in `index.html`'s `<title>`, the page header (`AppLayout` title) and the README; the product language sets `<html lang>` and every text the end user sees (labels, headings, error messages, the loading and error states), while code, tests names and logs stay in English; the backend's local URL is `VITE_API_URL`.

## Verify in a browser

The generator's `.claude/skills/new-project/tools/check-page.cjs` does this: run it with the `zenika/alpine-chrome:with-puppeteer` image (`--entrypoint node`, `NODE_PATH=/usr/src/app/node_modules`, `TARGET_URL` set, the output folder mounted at `/out` where the screenshot lands, `--add-host host.docker.internal:host-gateway`). Tests with a mocked API prove the screens; only a real browser proves the two repositories work together. With the backend and the dev server running, open the home page in headless Chrome (Puppeteer), wait for the content, print the visible text and the console messages, and take a phone-sized screenshot. The page must show the version the backend returned and the console must have no errors or warnings. A browser that runs in a container reaches the host as `host.docker.internal`: add that origin to the backend's `CORS_ALLOWED_ORIGINS` and to Vite (`__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS`) for the check, and point `VITE_API_URL` at it.

## Dev commands

The `project` script maps each command to the `package.json` script of the same name (`recipes/dev-commands.md`); `test:unit` and `test:integration` are the two Vitest projects, `audit` is `pnpm run audit`, and `size` builds and runs size-limit.
