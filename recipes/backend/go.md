# Go

The Go backend Stack Recipe. It follows `recipes/backend/clean-architecture.md`, whose **Code rules, Testing rules and Extra mechanisms rules** apply as written; this recipe only says how Go meets them and which tools it uses.

## Status: learning stack

The user is learning Go, so Go is in the menu as a **learning stack**, an explicit exception to the "only technologies the user masters" principle of `recipes/decision-guide.md`:

- The recipe is complete, with the same clean architecture and Quality Gates as every other stack.
- **The decision guide never recommends Go** for client projects or projects with a team; it is used only when the user explicitly asks for it, on personal projects.
- **In Go projects, the agent explains its idiomatic choices in every pull request** (why a channel, why this `defer`, why an interface sits where it does), so each review also teaches.
- The gates are stricter to make up for less experienced review: a broader `golangci-lint` rule set and the race detector (`go test -race`) on every run.
- When the user feels confident in Go, the "learning" status is dropped and Go becomes a regular stack.

## Choices

- **HTTP: the standard library (`net/http`) + Huma.** Since Go 1.22, `net/http` routes by method and path parameters (`GET /v1/roles/{id}`) with no framework. **Huma** sits on top: routes declared with Go types, request validation, the **OpenAPI 3.1 spec generated from code** (ADR-0008), and errors returned as **Problem Details** natively (ADR-0011). Starting from the standard library also teaches idiomatic Go.
- **Structure and names: the same map as the other recipes, with Go file names.**
  - Folders: `internal/domain`, `internal/application/usecases/role`, `internal/application/dtos/usecases/role/createrole`, `internal/infra/…`; entry points in `cmd/api` and `cmd/<function-or-batch>`. **Folder names are lowercase**, because a Go package is named after its folder and package names are lowercase with no underscores (`usecases`, `checkhealth`), unlike the camelCase folders of the other recipes.
  - **Type names are the same as in every other recipe** (`CreateRoleUseCase`, `RoleRepositoryInterface`, `CreateRoleUseCaseInputDto`), so the same design is recognizable in any language, deliberately over Go's habit of short names without an `Interface` suffix.
  - **File names in `snake_case`**, as Go tooling and the community expect (`create_role_use_case.go`).
  - **Errors are values**: a `BusinessError` type carrying an `ErrorCode`, returned (`return nil, exceptions.NewBusinessError(enums.RoleAlreadyExists)`), never `panic`; the global handler turns it into Problem Details. This is Go's form of the single `BusinessException(ErrorCode)` of ADR-0011. The constants are CamelCase (`RoleAlreadyExists`) and their value is the `UPPER_SNAKE` code the API returns (`"ROLE_ALREADY_EXISTS"`): revive rejects `ALL_CAPS` names.
  - Dependency injection is manual, wired in `main` (the composition root).
- **How Go meets the general rules**:
  - **Framework-free inner layers**: no Huma, `net/http`, sqlc, driver or SDK imports in `internal/domain` or `internal/application` (arch-go / depguard); dependencies arrive through constructor functions (`NewCreateRoleUseCase(roleRepository RoleRepositoryInterface)`).
  - **Transactions**: `pgx.Tx` / `sql.Tx`, only inside repositories.
  - **Types**: dates are `time.Time` in UTC; money is `int64` cents in a `Money` value object, never `float64`; enums are typed constants (`type ErrorCode string` with `const` values); a lookup that may find nothing returns `(Role, bool)` or `(*Role, error)` with a sentinel `ErrNotFound`, never a zero value as "not found"; slices returned empty, never `nil`, when a list is expected.
  - **DTOs and value objects** are structs passed by value with unexported fields and constructor functions for value objects (so they stay valid); mapping is hand-written (`fromRow` / `toDto` functions); repositories never return sqlc rows.
  - **Tests**: mockery mocks for ports only, generated into `tests/mocks`; builders and the test application in `tests/helpers`; the database reset between integration tests.
  - **Mechanisms**: in-process schedulers (`robfig/cron`, `time.Ticker` jobs) are forbidden; consumers are push.
- **Conventions enforced by tools**: `gofmt` / `goimports`; golangci-lint (`revive` naming, `funlen`, `gocyclo`, `dupl`, `errcheck`, `forbidigo` against `fmt.Print*` and `panic` outside `main`); arch-go for the layer rules and for use cases exposing only `Execute` (Go exports by capital letter, so the method is `Execute`).
- **Implementation notes**: configuration from environment variables (`caarlos0/env`), validation messages shown to end users in the product's language, `slog` JSON handler with the request ID from the `context.Context`.
- **Plain Go**: Go has no framework split (the standard library is the base), so Event Functions use the same stack without Huma: a binary in `cmd/<function>` with the per-platform adapter in `internal/infra/functions/`.
- **Database: sqlc + goose.** Queries are plain SQL in `.sql` files and **sqlc generates typed Go functions** from them; migrations are numbered SQL files applied by **goose**. Same spirit as Drizzle in Node: explicit, typed SQL. Drivers: `pgx` (PostgreSQL), `go-sql-driver/mysql` (MySQL). Generated code stays in `internal/infra`.
- **Tests and quality**:
  - `testing` + **testify** (assertions) + **mockery** (generated mocks for ports); integration tests against the real database of the Compose `db` service, in its own `app_test` database (ADR-0003), like the other recipes. testcontainers-go is not used: it needs the Docker socket inside the dev container and inside CI's `docker compose run`.
  - **golangci-lint** with a broad rule set: complexity, length and duplication limits (`gocyclo`, `funlen`, `dupl`), style (`revive`), ignored errors (`errcheck`), plus the default linters.
  - **`go test -race`** on every run.
  - **arch-go** for architecture validation; `gofmt` / `goimports` (golangci-lint's formatters) for formatting.
  - **80% coverage** on `domain` + `application`.
- **Libraries**:

  | Category | Library |
  |---|---|
  | HTTP + validation + OpenAPI + Problem Details | `net/http` + Huma |
  | Database / migrations | sqlc + goose (`pgx` / `go-sql-driver/mysql`) |
  | Configuration | environment variables with `caarlos0/env` |
  | JSON logs | `log/slog`, request ID carried in the `context.Context` |
  | UUID v7 | `google/uuid` |
  | JWT / passwords | `golang-jwt/jwt` / `golang.org/x/crypto/argon2` |
  | Retry / circuit breaker | `cenkalti/backoff` / `sony/gobreaker` |
  | In-code rate limit | `golang.org/x/time/rate`; `go-redis/redis_rate` when shared |
  | Queue, events, file storage | `aws-sdk-go-v2` / `cloud.google.com/go` libraries |
  | Email (SMTP) | `wneessen/go-mail` |
  | Cache | `ristretto` per instance; `go-redis` when shared |
  | Long batch | a second binary in `cmd/<batch>`, run as an ECS task / Cloud Run Job |
  | Graceful shutdown | `http.Server.Shutdown` on `SIGTERM` |
- **Versions**: the latest stable Go release (Go has no LTS), following the version policy in `recipes/decision-guide.md`, pinned in `go.mod` (`go` and `toolchain` directives).
- **Runtime**:
  - **AWS Lambda**: a compiled binary on the `provided.al2023` runtime (very low cold start), packaged and deployed with the **Serverless Framework**, like PHP and Node; the HTTP API enters through one adapter file, `internal/infra/functions/api/lambda_handler.go` (`aws-lambda-go-api-proxy`), the same exception as Node. Everything else stays in Terraform, linked through SSM parameters (ADR-0002). Deploys run only in the pipeline, via OIDC.
  - **Containers**: the `Dockerfile` `prod` target is a **distroless static** image holding only the binary, non-root, that migrates at start and checks its own health (*Generating the project*, items 3 and 4); the `dev` target carries Go, the quality tools and hot reload (air).

## Generating the project

Learned from generating a Go backend end to end (run of 2026-11-04, `.scratch/go-backend/issues/01-generate-go-backend.md`). Go has no skeleton to create and clean up: every file is written. Follow in this order:

1. **Module**: `go mod init github.com/<owner-lowercase>/<slug>-backend` in the dev image, so the host needs only Docker; then `go get` the libraries of the table above at their latest release. `go.mod` keeps the `go <version>` line `go mod init` writes; the image sets `GOTOOLCHAIN=local` so no other toolchain is downloaded.
2. **The tools module**: the quality tools are pinned in a **separate module, `tools/go.mod`** (`module <module>/tools`), with `go get -tool <package>@<version>` for golangci-lint v2 (`github.com/golangci/golangci-lint/v2/cmd/golangci-lint`), arch-go, mockery v3, sqlc (`github.com/sqlc-dev/sqlc/cmd/sqlc`), govulncheck (`golang.org/x/vuln/cmd/govulncheck`), air and Lefthook v2 (`github.com/evilmartians/lefthook/v2`). The application's `go.mod` stays free of the tools' dependencies (golangci-lint advises against sharing them) and Renovate updates both. The `tools/` folder holds only `go.mod` and `go.sum`: the root module cannot run a Go program from a nested module, so no helper program lives there.
3. **The `Dockerfile`, three stages**:
   - `dev`: `golang:<version>-trixie` (it ships `gcc` for `-race` and `make`), `ENV GOTOOLCHAIN=local CGO_ENABLED=1`, `COPY tools/go.mod tools/go.sum /tools/` and `RUN cd /tools && go install tool` (every tool into `/go/bin`, so they run by name), `git config --system --add safe.directory /app`, `HEALTHCHECK NONE`, `CMD ["sleep", "infinity"]`;
   - `build`: the same Go image with `CGO_ENABLED=0`, `go mod download` before copying `cmd/` and `internal/` (a cached layer), `ARG APP_VERSION=dev` and `go build -trimpath -ldflags "-s -w -X main.version=${APP_VERSION}" -o /out/server ./cmd/api`;
   - `prod`: `gcr.io/distroless/static-debian13:nonroot`, only `/app/server`, `ENV APP_ENV=production`, `USER nonroot:nonroot`, `HEALTHCHECK CMD ["/app/server", "healthcheck"]`, `ENTRYPOINT ["/app/server"]`, `CMD ["serve"]`. Measured at **24.8 MB**.
4. **One binary, several commands** (`cmd/api/main.go`, the composition root's caller): `serve` (the default: runs the migrations, then listens, and on `SIGTERM` shuts down within `SHUTDOWN_GRACE_PERIOD`), `serve:no-migrate` (for a second process of the same image, so only one container migrates), `migrate`, `migrate:fresh` (drops the `public` schema and migrates; refuses unless `APP_ENV=local`), `healthcheck` (a `GET http://127.0.0.1:<port>/health` with a 3-second timeout; distroless has no shell or `curl`, so the image and both Compose files check health with the binary itself) and `openapi` (prints the specification). `version` is a package variable set by `-ldflags`; `APP_VERSION` in the environment overrides it.
5. **The composition root** is `internal/infra/config/application.go`: `NewApplication(ctx, config, version, logOutput)` builds the pool, the adapters, the use cases and the router, and the integration tests call the same function. `config.go` reads the environment with `caarlos0/env` (`APP_ENV`, `HTTP_PORT`, `LOG_LEVEL`, `CORS_ALLOWED_ORIGINS`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `DB_CONNECT_TIMEOUT` defaulting to `3s`, `SHUTDOWN_GRACE_PERIOD`) and builds the connection URL with `connect_timeout`.
6. **Huma on `net/http`** (`humago.New(mux, config)`): `DocsPath`, `OpenAPIPath` and `SchemasPath` empty (the contract is the committed file, not a served page) and `CreateHooks = nil`, which drops the `$schema` property and the `Link` header Huma adds to every response. Each controller has a `Register(api huma.API)` method with one `huma.Register` per operation (`OperationID`, `Errors` listing the Problem Details statuses it can return). `mux.HandleFunc("/", NotFoundHandler)` answers unknown routes with a `RESOURCE_NOT_FOUND` problem (a wrong method on a known path is also a 404 there). The filters wrap the mux: request ID outside, then CORS.
7. **Problem Details** (`internal/infra/config/problem_details.go`, ADR-0011): a `ProblemDetailsDto` (`type`, `title`, `status`, `detail`, `code`, `traceId`, and `errors` with `field` and `message` only for validation) implementing `huma.StatusError` and `ContentType` (`application/problem+json`). **Both `huma.NewError` and `huma.NewErrorWithContext` are replaced**: Huma derives the error schema of `openapi.json` from `NewError`, so replacing only the context variant keeps Huma's `ErrorModel` in the contract. A `BusinessError` in the errors maps to its `ErrorCode`; a 400 or 422 to `VALIDATION_FAILED` with the field errors; 404, 429 and the rest to their codes. `ErrorCode` has `Status()`, `Title()` and `Detail()`, with the texts in the product's language.
8. **Request ID and CORS** as `net/http` middlewares in `internal/infra/http/filters`: the request ID (incoming `X-Request-Id` up to 128 characters, else a UUID v7) goes into the response header and the `context.Context`, read by the logger and the Problem Details; CORS is written by hand: the allowed origins from `CORS_ALLOWED_ORIGINS`, credentials, `X-Request-Id` exposed, the frontend's headers allowed, `Vary: Origin`, a 204 preflight, and an unknown origin is never echoed.
9. **Logging**: `LoggerService` on `log/slog`'s JSON handler (stdout), level from `LOG_LEVEL` (an unknown value falls back to `info`), the request ID from the context as `requestId`, and the fields under `context` with the sensitive names masked as `***` at every nesting level. `LoggerServiceInterface` takes `(ctx, message, fields map[string]any)`.
9a. **`POST /v1/client-errors`** (`recipes/backend/clean-architecture.md`, Observability; the React frontend calls it from its global error listeners): `LogClientErrorUseCase` logs `client error` at `ERROR` with the `message`, `stack` and `url`; the body is validated by Huma's tags (`message` required, `minLength:"1"`, `maxLength:"1000"`; `stack` up to 8000 and `url` up to 2000, both optional pointers); `DefaultStatus` 204 and the handler returns `&struct{}{}` (golangci-lint's `nilnil` rejects `nil, nil`); rate-limited per client address by a Huma operation middleware over `golang.org/x/time/rate` (`CLIENT_ERROR_RATE_EVERY` `6s`, `CLIENT_ERROR_RATE_BURST` `10`), answering a `TOO_MANY_REQUESTS` problem with `Retry-After` through `huma.WriteErr`. Integration tests: 204, 422 without `message`, 422 above 1000 characters, 429 above the burst. The first Go run left this out: the frontend's generated client then had no endpoint to call.
10. **Database**: `pgxpool`; migrations are goose SQL files in `internal/infra/database/migrations` (`00001_<snake_description>.sql`, `-- +goose Up`, `StatementBegin` / `StatementEnd` around a `DO` block), **embedded** with `//go:embed migrations/*.sql` and applied through `goose.UpContext` over `stdlib.OpenDBFromPool`. The embed pattern needs at least one file, so the first migration sets the database timezone to UTC (`ALTER DATABASE <current> SET timezone TO 'UTC'` through `format('%I')`). sqlc reads the same folder as its schema (`sqlc.yaml`: `engine: postgresql`, `queries: internal/infra/database/queries`, `out: internal/infra/database/sqlc`, `sql_package: pgx/v5`, `emit_empty_slices: true`); the health repository's `Ping` (`SELECT 1::integer AS reachable`) is the first query, run with the configured timeout. The generated files are committed.
11. **Mocks** with mockery v3 (`.mockery.yml`: `all: true`, `template: testify`, `dir: tests/mocks`, `pkgname: mocks`, `structname: "{{.InterfaceName}}Mock"`, `filename: "{{.InterfaceName | snakecase}}_mock.go"`, the `application/repositories` and `application/services` packages). `project generate` runs `sqlc generate` and `mockery`.
12. **Tests** follow the shared layout (`recipes/backend/clean-architecture.md`, Tests) with lowercase package folders: `tests/unit/...` and `tests/integration/http/<feature>controller`, packages named `<folder>_test`, one `Test<Type>` function per type with `t.Run("should … when …", …)` subtests. `tests/helpers` has `LoadTestConfig`, `StartTestApplication` (migrates, then truncates every table but `goose_db_version`, then serves the real handler with `httptest`), `StartTestApplicationWithoutDatabase` (for the database-down case) and `Request`. The integration tests cover `/health` up and down (503 `DATABASE_UNAVAILABLE` with the `traceId`), an unknown route, and CORS (allowed origin, preflight, unknown origin).
13. **Gates in a `Makefile`** (Go has no script runner; `make` ships in the Go image), one target per command with `:` written as `-` (`test-unit`), which `project` maps:
    - `lint`: `golangci-lint fmt --diff` then `golangci-lint run`; `format`: `golangci-lint fmt`;
    - `typecheck`: `go build ./... && go vet ./...`;
    - `arch`: `arch-go --color no`;
    - `test-unit`: `go test -race -count=1 ./tests/unit/...`; `test-integration`: the same over `./tests/integration/...` with `DB_DATABASE=app_test` and `-p 1`;
    - `coverage`: `go test -race -coverpkg=./internal/domain/...,./internal/application/... -coverprofile=build/coverage.out ./tests/unit/...`, then `go tool cover -func` piped into an `awk` that fails below 80 (no helper program, item 2);
    - `audit`: `govulncheck ./...`;
    - `openapi`: `go run ./cmd/api openapi > openapi.json`; `openapi-check`: the same piped into `diff -u openapi.json -`, failing with "openapi.json is out of date: run ./project openapi";
    - `check`: `lint typecheck arch coverage test-integration openapi-check audit`, in that order, stopping at the first failure.
14. **golangci-lint v2** (`.golangci.yml`, `version: "2"`, `linters.default: standard`) enables `revive`, `funlen` (`lines: 30`, `statements: -1`), `gocyclo` (`min-complexity: 10`), `dupl` (`threshold: 50`), `forbidigo` (`^fmt\.Print.*$` and `^panic$`), `mnd`, `nestif`, `goconst`, `errorlint`, `wrapcheck` (ignoring the module's own packages), `nilnil`, `bodyclose`, `noctx` and `gosec`; revive rules `argument-limit` 4, `max-control-nesting` 3, `file-length-limit` 300, `flag-parameter`, `early-return`, `indent-error-flow`, `superfluous-else`, `empty-block`, `unused-parameter`, `var-naming`, with `exported` disabled. Exclusions: generated files (`generated: strict`), the size and duplication linters plus `wrapcheck`, `bodyclose` and `gosec` in `tests/` (test secrets are fixtures, which `gosec` G101 reports as credentials), `forbidigo` in `cmd/`. Formatters `gofmt` and `goimports` with the module as `local-prefixes`. The first run found 12 real issues in hand-written code (unclosed bodies, unchecked `Close`, a flag parameter, unwrapped errors, a 32-line function): write the code to these rules from the start.
15. **arch-go** (`arch-go.yml`, compliance and coverage thresholds 100): `domain` depends only on `domain`, `application` only on `domain` and `application`, both with **a `standard` allowlist** (`context`, `errors`, `fmt`, `maps`, `math`, `slices`, `sort`, `strconv`, `strings`, `time`, `unicode`, `unicode/utf8`) and `shouldNotDependsOn: external: ["**"]`; without the allowlist, `net/http` in `domain` passes, because the standard library is not "external". `infra` never imports `cmd` or `tests`; `tests` never import `cmd`; `cmd` imports only `internal/infra/config`. Contents: `application/repositories` and `application/services` hold only interfaces, `usecases` none. Functions in `usecases`: at most 4 parameters and 2 public functions per file (the constructor and `Execute`). Naming: structs in `infra/repositories` implementing `*RepositoryInterface` end in `Repository`, in `infra/services` implementing `*ServiceInterface` end in `Service`. The coverage threshold counts every package, so the `tests` packages need their rule too.
16. **Hot reload** with air (`.air.toml`: build `go build -o build/air/server ./cmd/api`, entrypoint `["build/air/server", "serve"]`, `include_ext` `go` and `sql`, excluding `build`, `tests`, `tools`, `.git`).
17. **Docker Compose** for development: `app` (target `dev`, `.env` as an optional `env_file`, port 8080, the repository at `/app`, named volumes for `/go/pkg/mod` and `/root/.cache/go-build` so modules and the build cache survive) and `db` (`postgres:<version>-alpine`, the volume at `/var/lib/postgresql`, `docker/postgres/init.sql` creating `app_test`, `pg_isready` health check). `docker-compose.prod.yml` as in `recipes/vps-deploy.md`, with the binary's `healthcheck` instead of `curl` and the `db` health check reading `$$POSTGRES_USER` and `$$POSTGRES_DB` from `stack.env`.
18. **`project setup`** runs `go mod download`, creates `.env` from `.env.example`, **loads it into the shell** (`set -a; . ./.env; set +a`: the container started before the file existed, so its environment lacks the variables) and then migrates, and `lefthook install`. **Write `lefthook.yml` before**: `lefthook install` creates a default one when it is missing.
19. **Repository files**: `.gitignore` (`.env`, `.env.*` but `.env.example`, `stack.env`, `/build`), `.gitattributes` (`* text=auto eol=lf`), `.editorconfig` (tabs for `*.go`, `go.mod`, `go.sum` and `Makefile`), `.dockerignore` (the list of `recipes/vps-deploy.md`, *Lean images*, plus the Go tool configurations; **not `tools/`**, which the `dev` stage reads), `.devcontainer/devcontainer.json` and `.vscode/settings.json` (`recipes/vscode-extensions.md`: `golang.go`, format on save with organize imports, `go.lintTool` `golangci-lint-v2`). Record the executable bit of `project`.
20. **Comments**: there is no skeleton, so nothing to strip; write no comments. The files sqlc and mockery generate keep their `Code generated … DO NOT EDIT` headers, which mark them as generated for golangci-lint and reviewers; goose's `-- +goose` lines are directives, not comments.
21. **Prove each gate failing once** (`recipes/quality-gates.md`), in a copy: `fmt.Println` in `domain` (forbidigo), `net/http` in `domain` (arch-go), an untested function in a use case (coverage below 80%), a changed operation summary (`openapi:check`). Then the `prod` image: build, `docker image ls` for the size, the production Compose file with a `stack.env` and its own project name, `GET /health` with the build's version, the health check `healthy`, the `goose_db_version` table filled, and `docker stop` exiting 0.
22. **The interview's answers** reach the backend like this: the slug gives the module path `github.com/<owner>/<slug>-backend` (lowercase), the container and Compose names and the Docker Hub image; the product name goes in the README and the OpenAPI title; the product language decides the texts of `ErrorCode` and every message the end user can see (code, logs and test names stay in English).
23. **Versions seen on 2026-11-04**: Go 1.27.3, PostgreSQL 18.6, Huma 2.40.0, pgx 5.12.0, goose 3.29.0, caarlos0/env 11.4.2, google/uuid 1.6.0, testify 1.12.1, golangci-lint 2.15.0, arch-go 1.7.0, mockery 3.9.0, sqlc 1.31.1, govulncheck 1.9.0, air 1.67.4, Lefthook 2.2.2, distroless `static-debian13`. Examples of the policy, not pins.

## Dev commands

The `project` script (`recipes/dev-commands.md`) maps each command to the `Makefile` target of the same name with `:` turned into `-` (`./project test:unit` → `make test-unit`, extra arguments as `ARGS`); `setup`, `db:seed`, `db:reset` and the `agents:*` commands live in the script itself. `start:dev` runs air. `check` runs `make check`, then `agents:check` when the agent team is installed.
