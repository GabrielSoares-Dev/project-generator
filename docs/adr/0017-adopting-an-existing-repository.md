# The agent team can be installed in an existing repository through an adoption pull request

Ensemble shows repositories that the GitHub App reaches but that have no agent team. Some of them were not generated by the Template, and regenerating them is not an option. The Generator routine (ADR-0016) therefore gains an **adoption**. It is an issue of the Template, labelled `project-adoption`, that names one repository. `adopt-scan <n>` reads that repository and posts a diagnosis without changing anything. `adopt <n>` runs `/new-project` in a new **adopt mode**, which opens one pull request in the repository with the agent rules, a `project` script over the tools it already uses, the CI callers and the agent team (`recipes/generator-routine.md`).

## Considered Options

- **Regenerate the repository from a recipe and move the code into it**: rejected. It rewrites working code and loses its history, and the user did not ask for a new project.
- **Install only the agent team (`agents-install`) and nothing else**: rejected. The roles run `./project check` and read `AGENTS.md`, and without them every ticket would fail or guess.
- **Rewrite the code to follow the recipe**: rejected. Where the repository differs, an ADR says the agents follow the repository there, and refactoring becomes ordinary tickets.

## Consequences

- The adopt mode never strips, reformats or rewrites existing code. Tests that already fail stay as they are and become issues; they are never skipped.
- The pull request is the only change, and the human merges it. The team is active only after the activation checklist (`recipes/agent-team-activation.md`).
- The Generator's session must reach the adopted repository. When it cannot, the user runs `/new-project adopt <n>` locally from the same issue.
