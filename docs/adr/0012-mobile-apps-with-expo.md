# Mobile apps are a third kind of repository, built with React Native and Expo

Besides backend and web frontend, a Derived Project may have a **mobile app repository**, built with React Native and **Expo**, a stack the user already masters. Its recipe follows the frontend's principles (Atomic Design with `state/`, `services/` generated by orval, `shared/`; the backend serves the screens). The agent's cloud session can write the code and run lint, typecheck, unit and component tests (Jest + React Native Testing Library, API mocked with MSW), but it has no iOS simulator (macOS only) and no documented Android emulator, so:

- end-to-end tests (**Maestro**) run in CI: Android emulator on Linux runners on every pull request, iOS simulator on macOS runners only on demand, since macOS minutes cost much more;
- Local Review happens on the user's phone through a development build pointed at the local backend (LAN IP or tunnel), opened from a QR code;
- builds and store submissions go through **EAS Build** and **EAS Submit** (no Mac needed), and JavaScript-only changes ship through **EAS Update**.

Because store releases are slow, a project with a mobile app is where server-driven UI beyond level 2 and a BFF (ADR-0007) are most likely to pay off; the decision guide raises them then.
