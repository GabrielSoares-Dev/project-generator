# Secrets live where they are used, and CI reaches the cloud through OIDC

> **Amended by ADR-0013 (2026-10-06):** on the VPS, CI holds only the Docker Hub token and the Portainer webhook URL as GitHub Actions secrets, and the application's runtime secrets are the stack's environment variables in Portainer. OIDC and the cloud secret managers below apply when a project moves to the cloud.

Each secret is stored next to whoever consumes it: the running application reads its secrets from the cloud's secret manager (AWS Secrets Manager / SSM Parameter Store, GCP Secret Manager), created by Terraform; CI and deploy workflows use GitHub Actions secrets and authenticate to AWS or GCP through **OIDC**, with no long-lived cloud access keys stored anywhere; the agent's cloud sessions get theirs from the session environment settings; local development uses a git-ignored `.env` with a committed `.env.example`. This deliberately replaces the `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` repository secrets used by `GabrielSoares-Dev/Boilerplate-spring-boot-serverless`: a leaked static key grants cloud access until someone notices, while an OIDC token is short-lived and scoped to one repository and workflow.

Cloud resources are created **only by the pipeline**. The single exception is a one-time bootstrap per project (`infra/bootstrap/`), applied by the user with their own credentials, which creates only what the pipeline cannot create for itself: the OIDC trust and the Terraform state bucket.
