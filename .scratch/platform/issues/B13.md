# feat: ticket timeline

Repository: ensemble-backend

## Context

The ticket screen (M1) shows the stages, the timeline built from the events and GitHub, the criteria and the pull request with its checks.

## User story

As the owner, I want one page per ticket, so that I can see who did what and decide from there.

## Acceptance criteria

- Given a ticket, when `GET /v1/tickets/{id}` is called, then it returns its stages, the timeline (handoff notes, verdicts with evidence, returns, PRs and checks, the owner's comments) newest first, and its acceptance criteria with their state.
- The actions it allows come as booleans (`canRetry`, `canPause`, `canAbandon`, `canDecide`).

## Contract changes

`GET /v1/tickets/{id}`.
