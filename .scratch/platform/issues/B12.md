# feat: notifications

Repository: ensemble-backend

## Context

Notifications live in the platform only, no push (M2): a counter, a list with filters, one per event, replaced while unread, read when resolved; plus the optional daily digest.

## User story

As the owner, I want to see what waits for me in one list, so that I never miss a decision.

## Acceptance criteria

- Given pending decisions, escalations, stalls, quota pauses and merges, when they happen, then one notification each is created, and a newer one for the same ticket and kind replaces an unread older one.
- Given `GET /v1/notifications?filter=&kind=&page=&size=`, then the list is paginated with the unread count; `POST /v1/notifications/read-all` marks them read.
- Given the thing resolved (decided, `/ok`, merged), then its notification is read on every screen through `notification.changed`.
- Pending decisions, escalations, stalls and quota cannot be turned off; merge and digest can.
