# feat: event log and GitHub webhook ingestion

Repository: ensemble-backend

## Context

Everything the screens show comes from an append-only event log (A3), fed first by GitHub webhooks, processed in the request and idempotent by delivery id (A4, D9).

## User story

As the owner, I want every change on my repositories recorded once, so that the screens are right even when GitHub sends a delivery twice.

## Acceptance criteria

- Given a delivery with a valid `X-Hub-Signature-256`, when `POST /v1/webhooks/github` receives it, then one `events` row is written with `dedupe_key` `github:<X-GitHub-Delivery>` and the answer is `204` in under a second.
- Given the same delivery again, when it arrives, then no new row is written and the answer is still `204`.
- Given a wrong signature, when it arrives, then the answer is `WEBHOOK_SIGNATURE_INVALID` (401) and nothing is written.
- Given the `events` table, when any code tries to update or delete a row, then there is no repository method to do it.
- Each write sends `NOTIFY ensemble_events, <seq>`.

## Contract changes

`POST /v1/webhooks/github`; `ErrorCode` `WEBHOOK_SIGNATURE_INVALID`. New ADR: the event log and projection.
