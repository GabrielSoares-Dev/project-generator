# feat: probable quota pause and probe

Repository: ensemble-backend

## Context

The platform cannot read the subscription quota, so it infers it (M4): 3 stalls of different roles or tickets in 30 minutes pause new starts, hold the retries, and a probe every 30 minutes releases one ticket.

## User story

As the owner, I want the team to stop wasting retries when the quota is out, so that work resumes cleanly when it is back.

## Acceptance criteria

- Given 3 stalls of different roles or tickets within 30 minutes, then a quota pause starts, new starts stop and every screen gets `pause.changed` with reason `quota`.
- Given a pause, when 30 minutes pass, then the scheduler releases one stalled ticket as a probe with the user's token (D4); a verdict ends the pause and the stalled tickets return one at a time without counting a retry.
- Given `POST /v1/quota/resume {reason}`, then `quota` resumes now and `not-quota` treats the stalls as usual.

## Contract changes

`POST /v1/quota/resume`.
