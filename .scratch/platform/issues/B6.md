# feat: live updates over SSE

Repository: ensemble-backend

## Context

The live screens and the team wall update through Server-Sent Events (T3), woken by PostgreSQL `LISTEN/NOTIFY` with replay from the log (D2). Stream contract in the Architect's plan (`.scratch/platform/architecture.md`), section 6.

## User story

As the owner, I want the screens to update by themselves, so that I never refresh to see what the team did.

## Acceptance criteria

- Given a signed-in user, when `GET /v1/stream` is opened, then it answers `text/event-stream` with `X-Accel-Buffering: no`, an `id:` equal to the event `seq` and a `: ping` every 15 s.
- Given `Last-Event-ID`, when the stream reconnects, then every event after it is replayed before the live ones.
- Given five minutes open, then the stream ends with `retry: 2000`; given the browser leaving, then its goroutine ends.
- One hub per process holds the `LISTEN` connection; a test opens and closes streams and checks no subscriber is left (risk R2).
- Events are hints: `ticket.changed`, `agent.changed`, `notification.changed`, `pause.changed`, `activity.appended`.
