# feat: login with GitHub through the platform's App

Repository: ensemble-backend

## Context

Only the owner's GitHub account may enter (A2), and every write to GitHub is done as the user with the App's user-to-server token (A1). Contract: *Auth and access* in the Architect's plan (`.scratch/platform/architecture.md`), section 6; risk R3 (single-use refresh tokens).

## User story

As the owner, I want to sign in with GitHub and stay signed in, so that Ensemble can act on GitHub as me.

## Acceptance criteria

- Given a visitor, when `GET /v1/auth/github/start` is called, then it redirects to GitHub with a `state` kept in a short-lived signed cookie.
- Given GitHub's callback with a valid `state`, when the user is the owner (`OWNER_GITHUB_LOGIN`, pinned to its id at first login), then the token is stored encrypted, the `session` and `logged_in` cookies are set and the browser goes to the app.
- Given another GitHub account, when the callback arrives, then no session is opened and the answer is `AUTH_NOT_OWNER`; a wrong `state` gives `AUTH_STATE_INVALID`.
- Given an expired access token, when two requests refresh it at once, then the refresh happens once, inside a row lock on `github_credentials`.
- Given a refresh GitHub refuses, when any request needs the token, then the session ends with `SESSION_EXPIRED`.
- Every `/v1` route except the public ones (`/v1/auth/*`, `/v1/webhooks/github`, `/v1/dispatcher-events`, `/v1/client-errors`, `/v1/display-pairings` start) requires the session and answers `UNAUTHENTICATED` without it.

## Contract changes

the auth endpoints of the plan's section 6; `ErrorCode`s `AUTH_STATE_INVALID`, `AUTH_NOT_OWNER`, `SESSION_EXPIRED`, `UNAUTHENTICATED`. New ADR in both repositories: GitHub App login and acting as the user (D3).
