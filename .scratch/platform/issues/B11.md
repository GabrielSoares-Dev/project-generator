# feat: scheduler process and the 15-minute reconciliation

Repository: ensemble-backend

## Context

A second command of the same binary runs the timed jobs in its own container (A4, D8); the first is the reconciliation that compares the projection with GitHub.

## User story

As the owner, I want Ensemble to repair what it missed, so that a lost webhook never leaves a screen wrong.

## Acceptance criteria

- Given `server scheduler`, when it starts, then it never migrates and runs each job inside `pg_try_advisory_lock`, so two never overlap.
- Given a ticket whose GitHub state differs from the projection, when the reconciliation runs, then it writes a correcting event with `dedupe_key` `reconciliation:<repo>:<number>:<hash>`.
- Every run is recorded in `job_runs` with its result.
- `docker-compose.prod.yml` gains the `scheduler` service with the same image and `command: ["scheduler"]`.
