# feat: dispatcher events ingestion

Repository: ensemble-backend

## Context

The agent-team dispatcher can POST every decision it takes to `events-url` (agent-team v0.3.0). Each repository gets its own token.

## User story

As the owner, I want the dispatcher's decisions in the same log as GitHub's events, so that the screens know what the team did and why.

## Acceptance criteria

- Given a repository, when the owner issues its events token, then only its SHA-256 hash is stored and the token is shown once.
- Given a body with `Authorization: Bearer <token>` of the same repository, when `POST /v1/dispatcher-events` receives it, then one event is written with `dedupe_key` `dispatcher:<sha256 of body>` and the answer is `204`.
- Given a token of another repository, or none, then the answer is `EVENTS_TOKEN_INVALID` (401); an unknown repository gives `REPOSITORY_NOT_REGISTERED` (404).
- Given the same body twice, then one event is written.

## Contract changes

`POST /v1/dispatcher-events`; `ErrorCode`s `EVENTS_TOKEN_INVALID`, `REPOSITORY_NOT_REGISTERED`.

## UI

none (the token is issued from the health screen, B14 and F9)

## Out of scope

asking agent-team to add an event id (noted in the plan).

none

the SHA-256 of the body
