# feat: decisions and the actions taken as the user

Repository: ensemble-backend

## Context

Decisions gathers everything waiting for the owner, and the actions run on GitHub as the user (A1, F1, F8).

## User story

As the owner, I want one list of what waits for me and buttons that act for me on GitHub, so that I lead the team from any screen.

## Acceptance criteria

- Given supervised hand-offs, `spec-ready` tickets, escalations, dependency fixes and merges, when `GET /v1/decisions` is called, then each comes with its project, both sides' evidence for escalations, and `canOk`, `canMerge`, `canTieBreak`.
- Given a hand-off waiting, when `POST /v1/tickets/{id}/ok` is called, then a `/ok` comment is posted as the user.
- Given a pull request ready, when `/merge` is called, then it is squash-merged as the user; when not allowed, `TICKET_ACTION_NOT_ALLOWED` (409).
- Given an escalation, when `/tie-break {winner}` or `/retry` is called, then the decision comment and labels follow F8 (the stage is restored and the return count resets).
- GitHub down gives `GITHUB_UNAVAILABLE` (502); a repository without the App gives `REPOSITORY_NO_ACCESS` (403).

## Contract changes

`GET /v1/decisions`, `POST /v1/tickets/{id}/ok|merge|tie-break|retry`.
