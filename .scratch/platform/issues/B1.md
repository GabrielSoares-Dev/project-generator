# feat: project registry and GitHub App installations

Repository: ensemble-backend

## Context

Ensemble follows several projects, each made of repositories where the platform's GitHub App is installed (A1 of the platform spec (`.scratch/platform/spec.md` in project-generator)). Every other feature reads this registry. Data model: `projects`, `repositories`, `app_installations` in the Architect's plan (`.scratch/platform/architecture.md`), section 5.

## User story

As the owner, I want Ensemble to know my projects and which repositories the App can see, so that every screen can be scoped to a project.

## Acceptance criteria

- Given an `installation` or `installation_repositories` webhook, when it arrives, then `app_installations` and `repositories` reflect the repositories the App can see, without duplicates.
- Given registered projects, when `GET /v1/projects` is called, then it returns each project with its repositories, kind and agent-team version, sorted by name.
- Given a repository without the App, when `GET /v1/account` is called, then it is listed as without access, with the App's install URL.
- Migrations follow the database naming of the conventions and only add.

## Contract changes

`GET /v1/projects`, `GET /v1/account` (registry part); the webhook endpoint itself is B3.
