# feat: projection of tickets and agent runs

Repository: ensemble-backend

## Context

The screens read a projection built from the events: each ticket's stage, flags and returns, and each agent run (A3).

## User story

As the owner, I want each ticket's current state computed from what happened, so that every screen agrees.

## Acceptance criteria

- Given the events of a ticket, when they are projected, then `tickets` has its stage, labels, `is_escalated`, `is_stalled`, `is_queued`, `is_awaiting_ok`, `returns_count` and `last_event_seq`.
- Given label events for a role, then `agent_runs` records when it started and ended.
- Given `serve projection:rebuild`, when it runs, then the projection is truncated and replayed and ends equal to what it was.
- The agent states (working, waiting for you, queued, stalled, free) are computed, never stored.
